# 思い出跡地

> 思い出は写真フォルダではなく、あの場所に残っている。

## このREADMEの目的

このファイルは、実装を担当するCodexがプロダクトの意図とMVPの境界を理解し、仕様を勝手に膨らませずに開発を進めるための基準書である。

実装上の判断で迷った場合は、機能の多さよりも次の体験を優先すること。

> 大切な人たちと以前訪れた場所へ再び近づいたとき、その場で撮った写真を見て、当時の記憶が走馬灯のように蘇る。

## 開発コマンド

- `npm install` — ロックファイルに従って依存関係をインストールする。
- `npm run start` — Expo開発サーバーを起動する。
- `npm run lint` — Expo・React Native・TypeScript向けのLintを実行する。
- `npm run format:check` — Prettierのフォーマット規約への適合を確認する。
- `npm run typecheck` — ファイルを生成せずにTypeScriptの型を検査する。

## 1. プロダクト概要

**思い出跡地**は、招待制グループ内で、アプリ内カメラで撮影した写真を現在地に紐付けて保存するモバイルアプリである。

ユーザーは地図上で「思い出がある場所」を鍵付き宝箱のようなアイコンとして確認できる。ただし、写真そのものは跡地の開封半径内に入るまで閲覧できない。

これは一般的な写真共有SNS、旅行記録アプリ、公開型の位置情報SNSではない。

- 写真を誰にでも見せるサービスではない
- フォロワー、いいね、公開フィードは持たない
- 写真を探して見るのではなく、場所へ戻ったときに思い出す
- 思い出は、共有した人間関係ごとに分けて残る

### 想定する利用例

- 恋人と初デートした店の近くで、その日の写真を再生する
- 地元の友達とよく集まった場所で、過去の写真を振り返る
- 家族で出かけた場所に再訪し、そのときの記録を見る
- 旅行先へもう一度訪れ、当時の写真を時系列で見る

---

## 2. MVPで検証する価値

MVPで検証したいことは一つだけである。

> 写真を撮った場所に戻って初めて開く体験は、普通のアルバムより思い出を強く蘇らせるか。

この体験に不要な機能はMVPに入れない。

## 3. MVPの機能

### 3.1 認証

- サインアップ
- ログイン
- ログアウト

最初はメールアドレスとパスワードによる認証でよい。

### 3.2 グループ

グループは「誰と共有する思い出か」を分ける単位である。

- グループを作成できる
- 無料ユーザーは**最大5グループ**まで作成できる
- 1グループのメンバーは**最大10人**
- グループ名を設定できる
- 作成者は招待リンクまたは招待コードでメンバーを招待できる
- 招待されたユーザーは承諾または辞退できる
- メンバーは自分でグループから退出できる
- 作成者はメンバーを削除できる
- 作成者はグループを解散できる

#### 閲覧権限ルール

- 現在グループに所属しているメンバーは、そのグループの過去・現在の跡地を閲覧できる
- 後から参加したメンバーも、過去の跡地を閲覧できる
- グループを退出した、または削除されたメンバーは、過去・現在を含むすべての跡地を閲覧できなくなる
- 再参加した場合は、再び閲覧できる
- グループを解散すると、グループ内の跡地は全員から閲覧できなくなる

グループへ招待すると過去の跡地の正確な位置も地図上に表示され、開封半径内では写真も閲覧可能になるため、招待承諾画面にはその旨を明記すること。

### 3.3 地図と跡地

- アプリ起動後のデフォルト画面はGoogle Maps
- 所属グループの跡地を地図上に表示する
- 跡地は**鍵付き宝箱など、中身が分からないアイコン**で表示する
- 地図上に写真サムネイル、投稿者名、メモ本文は表示しない
- 同じグループで、既存の跡地から**50m以内**にある投稿は一つの跡地としてまとめる
- 50m以内に複数の跡地がある場合は、最も近い跡地へ追加する
- 跡地の位置は最初の投稿時の座標とし、写真が追加されても移動させない
- 写真が開けない状態でも、跡地の存在自体は地図上で分かる
- 現在グループに所属しているメンバーには、遠方からでも跡地の正確な位置を表示する

### 3.4 開封半径

- 開封半径は写真単位ではなく、**跡地単位**で設定する
- 新しい跡地を作成する投稿者は、作成時に**150m**または**500m**を選択する
- 既存の跡地へ追加された写真は、その跡地の開封半径を引き継ぐ
- 跡地を作成したユーザー、またはグループ作成者は、作成後も150mと500mを切り替えられる
- 跡地作成者がグループを退出した場合も、グループ作成者は設定を変更できる
- 自由入力や150m／500m以外の値はMVPでは提供しない

150mは、店・公園・旅行先で「その場所に戻った感覚」を重視する場合の基準値である。500mは、学校、私有地、閉鎖施設、キャンプ場など、撮影地点の中心まで再び入ることが難しい場所で利用する。

自宅で撮影した思い出の保存は禁止しない。

### 3.5 写真投稿

- 投稿は**アプリ内カメラで撮影した写真のみ**
- 端末の写真ライブラリからアップロードする機能はMVPでは提供しない
- 撮影時の現在地を自動で保存する
- 投稿先のグループを一つ選択する
- 1投稿につき写真は1枚
- 一言メモは任意
- 同じグループの既存跡地から50m以内で撮影した投稿は、その跡地に蓄積する

アプリ内カメラ限定は、過去に撮った画像を任意の場所に置くことを防ぎ、「その場で残した思い出」の価値を守るためである。

GPS偽装など、意図的なチートへの高度な対策はMVPでは行わない。通常のユーザーが他人の写真へアクセスできない権限管理を優先する。

### 3.6 跡地の閲覧

跡地に設定された開封半径（150mまたは500m）以内にいる場合だけ、写真を閲覧できる。

#### 同じ地点に一つのグループしかない場合

そのまま跡地の閲覧画面を開く。

#### 同じ地点に複数グループの思い出がある場合

最初に「この場所には複数の思い出があります」と表示し、グループを選択させる。選択したグループの写真だけを表示する。

例:

- 恋人
- 地元の友達
- 家族

同じ店や場所でも、誰と行ったかによって思い出は別物であるため、グループを混ぜて表示しない。

#### 表示形式

閲覧画面では、ユーザーが次の二つを選べるようにする。

- **一覧**: 写真をグリッド表示し、任意の写真をタップして見る
- **時系列で振り返る**: 写真を撮影日時の古い順に、左右スワイプで見る

時系列表示は、場所に蓄積された時間を感じるための重要な体験である。ただし、ユーザーに強制はしない。

### 3.7 削除

- 投稿者本人だけが自分の投稿を削除できる
- 削除した投稿は、グループの全員から閲覧できなくなる
- 跡地内の投稿が0件になった場合、その跡地アイコンは地図から消える
- グループ解散は破壊的な操作なので、グループ名の入力など強い確認を要求する

## 4. MVPでは作らないもの

次の機能はMVPの価値検証に不要なため、実装しない。

- 動画投稿・再生
- BGM
- 自動スライドショー
- 課金・サブスクリプション決済
- 公開グループ
- 全国の知らない人の跡地探索
- コメント、DM、いいね、フォロワー
- バックグラウンドでの到達通知
- 投稿の非公開を🧩で残す機能
- 投稿の復元依頼（最大2回）
- AIによる写真整理・要約

## 5. 将来の課金候補

課金処理自体はMVPで作らない。ただし無料枠を前提にデータ設計する。

### 無料枠

- グループ作成: 最大5
- 1グループ: 最大10人
- 写真投稿: 月30枚を想定

### 将来の有料機能候補

- グループ作成数の追加
- 月間写真投稿数の追加
- 高画質保存
- 15秒動画の投稿・再生
- 自動で写真を再生する「走馬灯ムービー」
- BGM付きの思い出再生
- 旅行・年単位での思い出振り返り

無料ユーザーにも「場所へ行くと写真が開く」という中核体験は必ず提供する。課金は、より多く・より深く・より演出的に振り返るためのものとする。

## 6. 推奨技術スタック

| 役割                   | 技術                              | 用途                                           |
| ---------------------- | --------------------------------- | ---------------------------------------------- |
| モバイルフロントエンド | React Native + Expo + TypeScript  | iOS / Androidアプリ、カメラ、現在地取得        |
| 地図                   | Google Maps SDK                   | 地図と跡地アイコンの表示                       |
| 認証・DB               | Supabase Auth + PostgreSQL        | ユーザー、グループ、招待、跡地情報             |
| 権限管理               | Supabase Row Level Security (RLS) | グループ外・退出後のユーザーをDB側で遮断       |
| 特別なサーバー処理     | Supabase Edge Functions           | 距離判定、署名URL発行、削除処理                |
| 写真ストレージ         | Cloudflare R2                     | 写真ファイルの保存                             |
| 位置検索               | PostGIS                           | 50m以内の跡地統合と150m／500mの開封判定        |
| アプリ配布             | Expo EAS Build                    | TestFlight / Google Play / App Store向けビルド |

MVPではRails APIやRenderの常時稼働サーバーは使わない。Supabaseが認証・DB・基本APIの役割を担い、Edge Functionsが必要なバックエンド処理を担う。

## 7. セキュリティと権限の必須ルール

チート対策ではなく、通常のユーザーの写真と位置情報を守ることを優先する。

- 写真を公開URLで保存しない
- 写真を開く前に、ログイン状態・グループ所属・削除状態・距離を確認する
- 条件を満たした場合だけ短時間有効な署名URLを発行する
- グループ外のユーザー、退出済みユーザーには写真・メモ・位置情報を返さない
- フロントエンドで隠すだけではなく、RLSとEdge Functionsでサーバー側でも検証する
- パスワードは平文保存しない
- Google Maps APIキーはiOS Bundle ID / Android Package Nameで制限する

正規に閲覧できるユーザーによるスクリーンショット保存までは防がない。守るべきなのは、権限のないユーザーが写真へアクセスできないことと、退出後に新たな閲覧URLを取得できないことである。

## 8. MVPの最重要ユーザーフロー

### 投稿

1. ユーザーがアプリを開く
2. 地図画面からカメラを起動する
3. 写真を撮影する
4. 保存先グループを選択する
5. 新しい跡地を作る場合は、開封半径を150mまたは500mから選択する
6. 任意で一言メモを入力する
7. 現在地とともに保存する
8. 地図上に鍵付き宝箱の跡地が現れる

### 再訪・閲覧

1. ユーザーが過去に写真を撮った場所の近くへ行く
2. 地図上の鍵付き宝箱をタップする
3. 跡地に設定された開封半径の外なら、中身は開けない
4. 開封半径内なら、跡地を開ける
5. 複数グループの跡地があれば、先にグループを選択する
6. 一覧または時系列表示で、その場所の写真を見る

## 9. Codexへの実装指針

- MVP外の機能を追加しない。必要に見える機能でも、まず提案して確認を取る
- 画面の見栄えより、写真投稿・グループ権限・半径内閲覧の一連の体験を優先する
- 5グループ上限、10人上限はフロントエンドだけでなく、DBまたはサーバー側でも必ず検証する
- 位置情報の扱いは必要最小限にし、写真閲覧の条件判定以外で追跡目的に利用しない
- Google Mapsはデフォルト画面とし、跡地の中身は地図上に表示しない
- テストでは、同じ地点に複数グループの跡地があるケース、50m境界で跡地が正しく分かれるケース、脱退後に閲覧できないケース、150m／500mそれぞれの半径外で開けないケース、半径を変更できるユーザーが正しく制限されるケースを必ず確認する
